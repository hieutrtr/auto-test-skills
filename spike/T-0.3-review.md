## Findings (3-5 bullets cho memo cuối Phase 0)

1. **The expensive decision was "structure or raw" for `run.log`.** It is
   tempting to wrap every line in JSON for `jq`-friendliness, but the
   read-budget (G2 ≤ 5s) is met by `manifest.json` + `run.json` *without*
   structuring the raw log. Keeping `run.log` plain text preserves the
   `tail -f` / `Read` ergonomics the personas rely on (PRD §2 Persona A
   "open browser, click thử"). If a future skill needs structured event
   timing (flaky-detector retry sequence), it gets `events.ndjson`
   side-by-side — incremental, optional. Net: file-format choice is
   **per-artifact**, not "one format to rule them all".

2. **Per-source stream files dodges the entire `O_APPEND` debate.** Spending
   the spike on flock vs PIPE_BUF vs cross-platform atomicity would have
   eaten T-0.4's budget. Making each layer (`unit`, `integration`, `browser`,
   `orchestrator`) write its **own** file removes the contention by
   construction; the only writer to a given file is one process. The
   merge is a `cat` at finalize — boring on purpose. T-0.4 still benchmarks
   100 concurrent appends to validate, but the bar is "demonstrate the rejected
   single-file approach corrupts under load and the chosen per-source path
   doesn't" — not "tune flock".

3. **`manifest.json` is the load-bearing artifact, not `run.log`.** The
   ARCHITECTURE §(d) loop contract reads four fields from `manifest.json`
   (`exit_code`, `summary`, `failed_cases`, `log_path`). Those are the
   keys that **must** stay shape-stable across schema versions. Everything
   else (artifact pointers, `redactions_applied`, layer list) is advisory
   and can evolve. Phase 1 implementation should derive a TypeScript /
   JSON-schema type **just for these four fields**, treat them as the public
   API, and keep the rest internal. Carry to T-0.5 memo as the
   "schema-versioning rule" decision.

4. **Retention is lazy on purpose.** The "no daemon, no cron" PRD constraint
   forces the cleanup pass into the auto-test critical path. With < 50ms
   added at run start, the trade-off is acceptable — but Phase 1 must
   measure (e.g. project with 100 stale runs, what's the readdir+mtime cost?)
   and document the upper bound. Note for T-0.4: after the prototype, run
   one synthetic measurement of cleanup cost on a folder with 50 fake runs.

5. **Worktree-friendly is a feature multiplier, not a checkbox.** PRD §6
   names it as a privacy property; the design also gets concurrent-run
   safety from the same property (R4 mitigation). claude-bridge worktree
   pattern means each agent loop iter has its own `.test-runs/` — no
   cross-iter contention. This means we can keep concurrency design
   *boring* (no global lock, no cross-process coordination) precisely
   because the worktree boundary already serializes inside-one-worktree
   runs. Worth highlighting in the install/integration doc (Phase 4) so
   users keep that property.

## Issues / Pivot

- **No pivot.** Design space is closed for the artifacts ARCHITECTURE §(b)
  enumerates. Open carry-overs are implementation-time choices (T-0.4) and
  one tooling pick (T-0.5 — Bun vs Node runtime), not design re-opens.

- **Open carry-overs to T-0.4** (mechanical implementation):
  1. Pick stream-merge tool (`cat` vs runtime fs API).
  2. Inline secret-redact via `tee` filter (rejected post-write).
  3. Windows fallback path (`LATEST.txt`) — implement minimally, document.
  4. 100-concurrent-append benchmark on per-source streams + a baseline
     run on shared `O_APPEND` to make the rejection visible.

- **Open carry-overs to T-0.5 memo**:
  1. Bun vs Node runtime decision (design memo is runtime-agnostic).
  2. Schema-versioning bump rule ("additive = no bump, rename/remove = bump").
  3. Confirmation that the four-field `manifest.json` loop contract should
     be the externally-promised stable API while the rest stays internal.

- **Risk register update**:
  - **R4 (Concurrent run from multi-agent)**: design now has explicit
    isolation via per-worktree `.test-runs/` + per-source stream files.
    Status: mitigation locked at design level; benchmark in T-0.4 confirms.
  - **No new risks introduced.**
