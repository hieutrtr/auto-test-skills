## Acceptance Criteria (from plan)

> **Skill load, Claude tự call khi prompt match `description`.**

Refined for this task:

- [x] Skill folder `hello-test/` with valid `SKILL.md` (frontmatter parseable,
  required fields present, folder-name = `name`).
- [x] **TDD-light**: a tiny check (`validate-skill.sh`) that asserts SKILL.md
  parses + has required frontmatter fields, written **before** the skill
  itself; first run must FAIL meaningfully (RED), then PASS after SKILL.md is
  created (GREEN).
- [x] Trigger phrase is a unique fingerprint (`hello-test ping`) so any
  activation can be unambiguously attributed to this skill.
- [x] Manual-verify procedure documented for actual Claude Code discovery
  (drop into `~/.claude/skills/hello-test/`, optionally restart, observe
  trigger behavior on n=5 prompts).
- [x] Failure modes documented for the case where the spike sandbox cannot
  exercise Claude Code's skill discovery directly.

## Approach

**TDD-light spike** (per loop Rule 2: "0.2 prototype hello-test: TDD nhỏ — viết
test 'skill có thể load' trước khi tạo SKILL.md"):

1. Write `spike/code/tests/validate-skill.sh` — a parameterized bash linter
   that, given a skill folder path, asserts:
   - Folder exists, `SKILL.md` at root.
   - File starts with `---` frontmatter delimiter; closing `---` present.
   - Frontmatter contains `name:` and `description:` fields.
   - `name` value equals folder basename (T-0.1 open-Q).
   - Description ≥ 40 chars (heuristic for trigger keyword density).
   - Body content present after frontmatter.

2. Run validator against an empty target — expect non-zero exit + "SKILL.md
   not found" failure (RED state, captured in review).

3. Write `spike/code/skills/hello-test/SKILL.md`. Frontmatter:
   - `name: hello-test` (matches folder).
   - `description:` ~700 chars, four-part anatomy from T-0.1 §5 (when /
     capability / keyword / anti-pattern). Trigger fingerprint: literal
     phrase `hello-test ping` — pseudo-unique, low false-positive risk.
   - `allowed-tools: Bash` (canonical field per T-0.1 finding #2).
   - Body: When-to-use → How-to-respond (single deterministic bash one-liner)
     → Examples (positive + 3 negative).

4. Re-run validator — expect 8/8 PASS (GREEN). Record both runs in review.

5. Document **manual verification** procedure for Claude Code discovery:
   - Sandbox limitation: this iteration runs inside a Claude Code agent
     session that cannot deterministically introspect its own skill-discovery
     hook (no MCP tool exposes "list discovered skills"; no API to reload).
   - Manual procedure: drop folder to `~/.claude/skills/hello-test/`, restart
     Claude Code (or open new session), prompt with the 5 test cases below,
     record activation outcomes. Outcome → input to T-0.5 memo (G5 evidence).

## Manual Verification Procedure (for human / future iter)

Reproducible in 5 minutes on a fresh Claude Code install:

```bash
# 1. Install (drop-folder)
cp -r spike/code/skills/hello-test ~/.claude/skills/

# 2. Restart Claude Code session (or open new chat — depends on PRD claim)

# 3. Run 5 test prompts in a fresh session and record activation:
#    P1 (positive):  "hello-test ping"
#    P2 (positive):  "Please run hello-test ping for me"
#    P3 (negative):  "hello world"
#    P4 (negative):  "run a test"
#    P5 (negative):  "ping the server"

# Expected:
#    P1, P2 → skill fires, output begins with "HELLO-TEST-PONG <iso-date>"
#    P3, P4, P5 → skill does NOT fire (no PONG output)

# 4. Cleanup
rm -rf ~/.claude/skills/hello-test
```

**Pass criterion**: ≥ 4 / 5 outcomes match expectation → G5 ≥ 80% achievable
on minimal sample → continue to T-0.5 memo with GO recommendation. < 4 / 5 →
investigate, possibly enrich description with more anti-pattern examples
(per xlsx pattern) or pivot to plugin packaging.

**Restart question** (T-0.1 open-Q #1): run sequence twice — once without
restart, once with restart — to determine whether restart is required. Log
result in T-0.5 memo.

## Notes / Open Questions

- **Q1 — Sandbox cannot fully verify**: this iter runs inside a Claude Code
  agent session, which has no introspection tool to list discovered skills or
  force a re-discovery. Validator + manual-verify procedure is the best we can
  do at this stage. → Findings handed off to T-0.5 memo + a future human pass.
- **Q2 — Description anti-pattern weight**: surveyed `xlsx`/`pdf`/`docx`
  description blocks include "Do NOT trigger when …" sections that explicitly
  enumerate negative cases. The hello-test description follows the same
  pattern with three concrete negative cases. If the manual run shows false
  positives on P3-P5, expand the negative list per `xlsx` style.
- **Q3 — `allowed-tools` field**: validator does not (yet) lint
  `allowed-tools` because T-0.1 surfaced uncertainty about whether `tools` or
  `allowed-tools` is canonical. Skill uses `allowed-tools` per T-0.1 finding
  #2. Future skills should re-use this validator and possibly extend it.
- **Q4 — Folder name vs `name` field**: validator enforces equality (T-0.1
  open-Q #2). Manual verify procedure does **not** test mismatch case — that
  would require a second probe skill, out of scope for this iter (deferred to
  T-0.5 memo's "open question" list).
