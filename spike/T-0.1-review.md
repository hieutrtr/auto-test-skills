## Findings (3-5 bullets cho memo cuối Phase 0)

1. **Frontmatter convention nhỏ gọn**: chỉ `name` + `description` required. `description` là router quan trọng nhất — Claude đọc metadata always-in-context để decide trigger. Bundled skills (xlsx/pdf/docx) viết description ~ 140-175 từ với 4 thành phần chuẩn (when/capability/keyword/anti-pattern). → Phase 1 mỗi SKILL.md viết description theo template này để max G5 (skill activation correctness ≥ 90%).
2. **`tools` field trong ARCHITECTURE.md không khớp thực tế**: skill thực (drawio) dùng `allowed-tools: Bash, Write`. → Phase 1 dùng `allowed-tools`; cập nhật ARCHITECTURE.md sau Phase 0 sign-off (out-of-scope task này theo Constraint "không modify ARCHITECTURE.md").
3. **File layout 3-tier**: `SKILL.md` (always loaded body) + `scripts/` (black-box, không vào context) + `references/` (load-on-demand). Pattern `pdf` skill (SKILL.md → forms.md / reference.md) là progressive disclosure tốt cho meta-skill `auto-test` (SKILL.md ngắn, detail per-runner ở references/). Skill-creator nhấn mạnh "Do NOT create README.md / CHANGELOG.md inside skill folder" — Phase 1 user-facing doc giữ ở repo root, skill folder lean.
4. **`webapp-testing` đã wrap Playwright** với layout `{SKILL.md, scripts/, examples/, LICENSE.txt}` — Phase 2 task 2.1 sẽ memo reuse. Sample script `with_server.py` (server lifecycle) có thể reuse trực tiếp cho `browser-test`. License: `Complete terms in LICENSE.txt` (proprietary check trong P2).
5. **Loadable mechanism chưa fully verified**: chưa test (a) restart Claude Code session có cần không, (b) folder name khác `name` field xảy ra gì, (c) `tools` vs `allowed-tools` field nào still valid. Task T-0.2 (`hello-test` prototype) sẽ resolve 3 câu này empirically.

## Issues / Pivot
