## 4. Self-review checklist (Rule 3)

- [x] **AC measured?** — yes, table §3.
- [x] **Reproducible?** — `bash skills/auto-test/tests/smoke.sh all` is hermetic
  per scenario: each bun run uses a fresh `mktemp -d` work dir trapped on
  function RETURN, so successive runs cannot collide. The fixture under
  `skills/unit-test-runner/tests/fixtures/bun/` is treated read-only (we
  copy it before mutating). Skip transcripts are deterministic — they
  encode only `host=`, `[skip:reason]`, and the static manual command
  list. Regression.log is identical to running each `run-all.sh` directly.
- [x] **Skill frontmatter valid?** — N/A (this task adds *test* artifacts,
  not a SKILL.md). The 3 production SKILL.md still pass `tools/lint-all.sh`
  via the regression hook.
- [x] **No secret leak?** — no env reads, no API keys, no hardcoded paths
  outside the project tree. Transcripts contain only public host metadata
  (`uname`, `bash --version`, `bun --version`) — no usernames, tokens, or
  network paths.
- [x] **Cross-platform (macOS / Linux), no GNU-only flags?** — audited:
  - `mktemp -d -t <prefix>.XXXXXX` — POSIX. Both BSD and GNU mktemp
    accept this form (BSD treats `-t` as a name template prefix; GNU
    prepends to TMPDIR). Tested on macOS 13 (Darwin 22 + Darwin 25) BSD.
  - `cp -R` — POSIX (vs GNU-only `--parents` / `--reflink`).
  - `printf '%s\n'` — POSIX.
  - `awk -F= '$1=="LATEST"{print $2}'` — POSIX awk only; no `getline`,
    no `gensub`, no `printf %c` extensions.
  - `grep -E`, `grep -q` — POSIX ERE.
  - `python3 -c 'import time; print(int(time.time()*1000))'` — same
    epoch-ms recipe used by `init-run.sh` from T-1.1. No `date +%N`
    (which is GNU-only on Linux and absent on macOS BSD).
  - `command -v <bin>` — POSIX.
  - `[[ ... ]]`, `[[ ... =~ ... ]]`, `${PIPESTATUS[0]}` — bash 3.2+;
    matches the toolchain established in T-1.1..T-1.7.
  - `trap '...' RETURN` — bash 3.2+; documented in `man bash`. Tested
    that work-dir cleanup fires (no leaked `/var/folders/.../autotest_smoke_*`
    after `smoke.sh all`).
  - **No** `stat -c`, **no** `date -d`, **no** `find -printf`, **no**
    `sed -i`, **no** `gzip --keep`, **no** `tee --append` (used `tee -a`
    if at all — actually no `tee` at all in final version).
  - `bash -n skills/auto-test/tests/smoke.sh` — passes.
- [x] **Smoke does not stomp on `spike/`** — harness uses `$skills_root` and
  `$repo_root/tools/tests/run-all.sh` only; never recurses into `spike/`.
  Verified by inspection (no `find` over the repo root) and by `git status -s`
  staying empty for `spike/` after a full smoke run.
- [x] **Smoke does not pollute git working tree** — only writes under
  `skills/auto-test/tests/smoke/`. Confirmed via `git status -s` before
  and after a fresh `smoke.sh all` invocation: no unexpected changes.
- [x] **Skip path does not mask real failures** — `record_skip` increments
  a separate counter and never feeds into `FAIL`. The harness explicitly
  exits 0 only when `FAIL == 0`; skips do not mask. AC-6 verified by
  re-running on this sandbox (no node) and confirming rc=0.

## 5. Findings

| ID  | Severity | Finding                                                                                          | Disposition                                                  |
|-----|----------|--------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| F-1 | low      | `regression.log` is verbose (485 LoC) — captures full output of every sub-suite. Future re-runs by contributors will overwrite it with their host's tally. | **accept** — verbosity is the point: this file is the canonical Phase-1 smoke baseline. Not asserted against, only emitted for forensic value. |
| F-2 | low      | `smoke.sh jest` and `smoke.sh vitest` always skip in the sandbox because node is absent. The "live" branch of `run_node_scenario` (when node + npm/pnpm are present) is therefore not exercised by automated CI here. | **accept** — covered by manual-fallback section (T-1.8-smoke.md §6) and PHASE-MANUAL-VERIFY.md (iter 10). The skip branch *is* exercised on this sandbox (positive evidence for AC-6). |
| F-3 | low      | The bun-pass `summary.total = 1` is reported as a single (implicit pass) suite/case rather than the per-test breakdown bun's text format technically supports. This is parser-side (T-1.4 known limitation), not orchestrator-side. | **accept** — orthogonal to the smoke contract; smoke only asserts shape (`total >= 1`, `failed == 0/>=1`). Per-case enrichment is on the Phase 4 backlog as documented in T-1.4 review. |
| F-4 | low      | `smoke.sh` does not run *concurrently* against multiple scenarios — it runs serially. Real-world CI that invokes auto-test concurrently across multiple projects could surface a race the harness wouldn't catch. | **defer** to Phase 4 — concurrency was already partially covered by the centralizer T-1.1 collision tests; harness-level concurrency would be a separate task. |
| F-5 | low      | The harness re-invokes `orchestrate.sh` once per scenario (no caching of the `bun install`-equivalent step — bun has no install step here). Total wall-clock for `smoke.sh all` on this sandbox: ≈ 6 s. | **accept** — well under any reasonable budget. |
| F-6 | low      | Smoke does not currently emit a JSON-shape rollup (only the human-readable `pass=X fail=Y skip=Z` summary). A future CI could parse the `RESULT: PASS\|FAIL` lines from the transcripts as a stop-gap. | **defer** — can add a `--json` flag when first consumer needs it; YAGNI for Phase 1. |
