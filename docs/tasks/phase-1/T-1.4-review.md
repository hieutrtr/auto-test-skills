### Findings

#### Fix-now (resolved within this iter)

1. **F-1 — stdin path bug discovered & fixed mid-iter.** The first
   draft used `python3 - "$input" <<'PYEOF'` which consumed bash's
   redirected stdin (the heredoc) and made `parser - < file` fail with
   "empty input" because the `sys.stdin.read()` branch saw an empty
   stream once heredoc was depleted. Switched to
   `PY_SCRIPT="$(cat <<'PYEOF' ... PYEOF)"` + `exec python3 -c
   "$PY_SCRIPT" "$input"` — stdin stays free for the user's piped data.
   Asserted by T1.4-23 (jest+bun stdin paths byte-equal file paths).

2. **F-2 — `validate-skill.sh` failed when invoked with `tests/..` path.**
   The validator compares `frontmatter.name` to `basename(input_path)`,
   so `tests/..` resolved to literal `..`. Test now does `cd "$HERE/.."
   && pwd` first to canonicalize before passing.

3. **F-3 — bun verbose-off mode dropping pass cases from per-suite
   detail.** Default bun reporter is silent on pass, but the summary
   block reliably reports the count. Parser reconciles by appending
   synthetic `"(implicit pass)"` cases to the first suite when
   `summary.passed > observed_pass` so totals stay correct. Documented
   in `parser-output-schema.md` §«Edge cases». Callers needing per-pass
   detail must run with `bun test --verbose`.

#### Defer (Phase 2 +)

1. **D-1 — Mocha + playwright-runner parsers.** Detection works
   (T-1.3 fixtures green) but `parse.sh` returns exit 2 with a clear
   "not yet implemented (Phase 4)" message. Out of T-1.4 scope.
2. **D-2 — Coverage % (line/branch) extraction.** Belongs to a future
   `coverage-reporter` skill (Phase 4 per PRD).
3. **D-3 — Flaky-rate annotation.** `cases[].retry_count` will be set
   by the Phase 4 `flaky-detector`; T-1.4 emits no `retry_count`.
4. **D-4 — Redaction.** Secrets in `error_stack` are passed through
   verbatim. Layer redaction in via the Phase 4 `redact-rules` config
   slot per PRD §6.
5. **D-5 — Vitest 2.x reporter format drift.** Vitest is conservative
   about reporter shape (Jest-compatible since v0.x), but a future
   v2.x might add new top-level fields. The `json.load` parser tolerates
   unknown keys; if the *required* keys (`testResults[].assertionResults[].
   {title,status,duration,failureMessages,ancestorTitles}`) ever change,
   the golden test will fail noisy on the next CI run with the new
   vitest version.
6. **D-6 — Run.sh wrapper (detect → invoke → parse).** This is T-1.5
   `auto-test/scripts/orchestrate.sh` work and intentionally not
   bundled with T-1.4.
