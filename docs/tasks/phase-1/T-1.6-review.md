## 4. Self-review checklist (Rule 3)

- [x] **AC measured?** — yes, table §3.
- [x] **Reproducible?** — `bash skills/test-log-centralizer/tests/test-retention.sh` is hermetic: every scenario uses a fresh `mktemp -d` subtree under `$TMP`, and trap removes it on exit. No reliance on wall-clock — IDs are seeded as static lex-sortable strings, so the ordering is deterministic across hosts.
- [x] **Skill frontmatter valid?** — `test-log-centralizer/SKILL.md` retains its T-1.1 frontmatter (`name: test-log-centralizer`, description ≥ 40 chars with trigger phrases + anti-patterns); only the `Files` and How-to-use code samples were extended for T-1.6. Will be `validate-skill.sh`-checked again in T-1.7.
- [x] **No secret leak?** — No hardcoded paths outside the project tree, no API keys, no env reads other than `TEST_LOG_RETAIN`. Test fixtures use mktemp-prefixed tmpdirs.
- [x] **Cross-platform (macOS / Linux), no GNU-only flags?** — audited:
  - `gzip <file>` — POSIX form (no `-k`/`--keep` BSD-only, no `--rsyncable` GNU-only). `gzip -c run.log > run.log.gz` would also work but plain `gzip` is shorter.
  - `gunzip -c <file>` — POSIX (used only in tests).
  - `rm -rf` — POSIX.
  - `ln -sfn` — works on BSD + GNU. Same form used by T-1.2 finalize-run.sh.
  - Sort: `printf '%s\n' "${runs[@]}" | LC_ALL=C sort` — POSIX, deterministic.
  - Array slicing: `${arr[@]:start:len}` — bash 3.2+. No bash-4 features.
  - `[[ ... =~ ... ]]` regex — bash 3.2+.
  - No `stat -c`, no `date -d`, no `readlink -f`, no `find -printf`.
  - `python3` only used in test for stat (st_ino + st_size); retain.sh itself has zero python dependency.

## 5. Findings

| ID  | Severity | Finding                                                                                          | Disposition                                                  |
|-----|----------|--------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| F-1 | low      | retain.sh writes nothing to stdout/stderr on success. The auto-test orchestrator currently invokes it through the `TEST_LOG_RETAIN=1` env in finalize, swallowing all output via `>/dev/null 2>&1`. If a future caller wants to log the action ("pruned 2, gz'd 2"), we'll need a `--verbose` flag. | **defer** to Phase 4 (PRD §6, observability tier). Phase 1 only needs the silent sweep. |
| F-2 | low      | `retain.sh` does not emit a 30-day age-based prune (ARCHITECTURE §(b) bullet 3). The doc in §5 of the task file calls this out. | **defer** to Phase 4 explicitly. Phase 1 scope is count-only. |
| F-3 | low      | The opt-in via `TEST_LOG_RETAIN=1` is observable to subprocesses — if a child framework's stdout reads `env`, the variable will be visible. Acceptable: the value carries no secrets. | **accept**. |
| F-4 | low      | If two `finalize-run.sh` calls race, two retention sweeps run concurrently. They are convergent (both compute the same target state), but a transient half-state could be observed by an intervening reader. | **defer** to Phase 4 (lockfile). Phase 1 callers are serial. |
| F-5 | low      | `KEEP_PLAIN=10` and `KEEP_GZ=2` are CLI args but not yet `<project>/.test-runs/config.json`-driven. | **defer** to Phase 4 per PRD §6. |
