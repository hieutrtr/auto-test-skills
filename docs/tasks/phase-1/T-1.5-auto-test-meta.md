## 4. TDD plan

### 4.1 Test framework

Continue with the project's `bash`-based test convention (consistent with
T-1.1..T-1.4 where bats was avoided to keep zero deps). Each test file is
a runnable bash script; `run-all.sh` per skill aggregates them.

### 4.2 Test files

- `skills/auto-test/tests/test-orchestrate.sh`
  - **AC-1**: drives orchestrate.sh against `unit-test-runner/tests/fixtures/bun/` (real `bun` available on dev machine; otherwise the test no-ops with skip-message exit 0 — documented as caveat).
  - **AC-2**: asserts `orchestrate.sh` resolves sibling skill (delete the symlink/path → expect exit 2 with "skill not found").
  - **AC-3**: parses produced `summary.json` — counts invariant.
  - **AC-4**: asserts dashboard contains `LATEST=`, `LOG=`, `JSON=` machine-readable lines.
  - **AC-5**: tests exit code on detection failure (empty dir → exit 2).
- `skills/auto-test/tests/test-render-dashboard.sh`
  - Pure-function test on `render-dashboard.sh`: feed pre-baked `summary.json` + `manifest.json` + `run.json` (under `tests/goldens/`); assert output contains expected lines (no ANSI, no time-sensitive substrings).
- `skills/auto-test/tests/run-all.sh`
  - Runs the two tests; exits 0 when both green.

### 4.3 Goldens

- `skills/auto-test/tests/goldens/sample-run/` — pre-baked run dir (handcrafted summary.json/manifest.json/run.json) so render-dashboard test does not depend on bun.
- Avoid byte-equal goldens for the *full* dashboard since duration_ms / timestamps drift; assert content presence (regex grep) instead.

### 4.4 Fixture re-use

- Use `skills/unit-test-runner/tests/fixtures/bun/` for E2E (already passing T-1.3 detection; `bun test` runs against `tests/sample.test.ts` which expects `3+3==6` → passes deterministically).

### 4.5 RED → GREEN order

1. Write `tests/test-orchestrate.sh` with assertions for un-built `orchestrate.sh` → run → red.
2. Write `unit-test-runner/scripts/run.sh` (orchestrator helper).
3. Write `auto-test/scripts/orchestrate.sh` (delegates to run.sh, then dashboard).
4. Write `auto-test/scripts/render-dashboard.sh`.
5. Write `tests/test-render-dashboard.sh` + goldens.
6. Run all green.
7. Commit.

## 6. Dashboard rendering (Phase 1 simplified)

Phase 1 dashboard is the **compact** form of PRD §7 (since only `UNIT` layer exists; integration / browser / manual are Phase 2-4 scope). Layout:

```
┌──────────────────────────────────────────────────────────────────┐
│  auto-test  ·  run <run_id>  ·  duration <Ms>ms  <status-icon>   │
├──────────────────────────────────────────────────────────────────┤
│  Project   : <project-basename>                                  │
│  Framework : <framework> (auto-detected)                         │
│  Command   : <command>                                           │
├──────────────────────────────────────────────────────────────────┤
│  UNIT          ✔ <P> passed   ✘ <F> failed    ⚠ <S> skipped       │
├──────────────────────────────────────────────────────────────────┤
│  FAILURES (≤ 3 lines each)                                       │
│   • <suite> › <case>                                              │
│       <error_msg first 60 chars>                                 │
├──────────────────────────────────────────────────────────────────┤
│  ARTIFACTS                                                       │
│    log       <abs path to run.log>                               │
│    json      <abs path to run.json>                              │
│    manifest  <abs path to manifest.json>                         │
├──────────────────────────────────────────────────────────────────┤
│  EXIT <code>   <message>                                         │
└──────────────────────────────────────────────────────────────────┘

LATEST=<abs path>
LOG=<abs path>/run.log
JSON=<abs path>/run.json
EXIT=<code>
```

The four trailing `KEY=value` lines are **machine-readable** so a
claude-bridge loop / agent grep-parses one line without parsing
the box-drawn table.

## 7. Risk + mitigation

| ID  | Risk                                                                 | Mitigation                                                               |
|-----|----------------------------------------------------------------------|--------------------------------------------------------------------------|
| R-1 | Meta-skill cannot invoke sibling skill (R-A from INDEX §10)         | `orchestrate.sh` resolves sibling via `$(cd "$(dirname "$0")/../.." && pwd)/unit-test-runner` — pure path math, no Claude-runtime dependency |
| R-2 | E2E test brittle when `bun` is absent in CI                          | Test detects `command -v bun`; if missing, prints `[skip-no-bun]` and exits 0 (logged in review). Manual verify covered by PHASE-MANUAL-VERIFY.md |
| R-3 | Dashboard golden drifts on every run (timestamp + duration)         | No byte-equal golden for the full dashboard; tests grep for content (`UNIT`, `EXIT`, `LATEST=`) — stable across runs |
| R-4 | Pipe `bun test 2>&1 | append-log.sh` loses framework exit code      | Use `set -o pipefail` + `${PIPESTATUS[0]}` in orchestrate.sh; documented in run.sh comments |
| R-5 | Long error_msg breaks ANSI box width                                 | Truncate to 60 chars + `…`; no ANSI / colors emitted |
| R-6 | `auto-test` triggers on every "test" mention (over-greedy)          | Description includes explicit anti-patterns ("not for: lint, type-check, build, browser e2e with dev server, coverage thresholds") |
| R-7 | sub-skill exit-code 2 (parse error) reported as 1 (test failure)    | `orchestrate.sh` distinguishes via run.sh exit code: 0 → 0, 1 → 1, ≥ 2 → 2 |
